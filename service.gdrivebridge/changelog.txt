v0.3.1 (2026-11-09)
- The setup QR code and address use the device's current home-network address, looked up each
  time you choose "Set up on phone or computer". Before, an address change while Kodi was
  running (a new DHCP lease) left the old address in the QR code until Kodi restarted.
- New: the GDrive Bridge repository. Install it once and Kodi keeps GDrive Bridge up to date
  (see the README for the steps).

v0.3.0 (2026-11-09)
- The setup page now opens only when you choose "Set up on phone or computer" in Kodi, and
  closes after 15 minutes idle. Safer default for a page on your home network. Upgrading
  switches an always-on page to this once; set Available back to "Always" in the settings if
  you prefer it.
- Passes Kodi's add-on checker for Kodi 21 and 22: needs Kodi 20 or later (xbmc.python
  3.0.1); the service starts at profile login; slim entry points; website and source links.

v0.2.0 (2026-11-09)
- Several Google accounts: each extra account is one more top-level folder (named after the
  account; rename or remove it on the setup page). Your existing paths don't change.
- Starred: a top-level folder of your starred files and folders.
- Search: "Search Google Drive" in the add-on's menu opens the matching files and folders as a
  folder you can browse and play.
- Pictures: "Add Google Drive to Pictures" helper. iPhone HEIC photos, which Kodi can't
  display, are listed as .jpg and served as Google's JPEG rendering (setting: "Show iPhone
  HEIC photos as JPEG").
- Read-ahead: subfolders of whatever Kodi opens are listed in the background, older copies
  are served at once and refreshed behind the scenes, and searches run before their window
  opens. Only a folder that has never been listed makes Kodi wait on Google. (On Kodi 21 we
  saw all of Kodi's Python add-ons freeze for up to 20 seconds while Kodi's screen waited on
  a slow folder.)
- .nfo files, artwork and subtitles next to your videos are read by Kodi's library as from
  any network share (no change needed; noted in the README).

v0.1.2 (2026-11-09)
- Setup page: stays logged in when opened from a link in another app (the login cookie
  was SameSite=Strict, which browsers don't send in that case).
- Setup page: "Choose the downloaded JSON file" picks the client file (on an iPhone, from
  Files) and saves it, so there's nothing to copy and paste.
- Sign-in without copy and paste: the setup guide now creates a Web application client that
  returns to this project's static relay page, which hands the sign-in to your Kodi device.
  Pasting the client's JSON file switches the relay on (Web client) or off (Desktop client)
  automatically. Desktop clients still work with copy and paste.
- Setup page: buttons no longer trigger Chrome's "The information you're about to submit is
  not secure" pop-up (forms are sent by the page's script). The address bar's "Not secure"
  label remains: the page is plain http on your home network.
- Setup page: "Settings saved" now shows after saving; re-signing in is easier to find
  ("Sign in again (or with another account)").
- Setup guide: the optional "Publish the app" step gives this project's home page and privacy
  policy URLs, and explains Google's harmless "branding not shown" and "requires
  verification" notices.

v0.1.1 (2026-11-09)
- Archive files (.zip, .rar, .7z, .apk and similar) are now hidden from Kodi by default.
  Why: Kodi treats archives as folders. When it lists a folder that contains one, it opens
  the archive to look inside, and it does this on its screen thread. Over Google Drive every
  read of an archive is a separate ranged download that takes a second or two, and reading
  one archive's index can take several. While that happens Kodi shows "Content Loading" and
  stops responding, for tens of seconds per archive. Kodi can't play archives anyway, so
  hiding them costs nothing. To show them again, turn off "Hide archives" in the Drive
  settings or on the setup page.
- Files and folders whose names start with a dot (.git...) are hidden by default ("Hide
  files and folders starting with a dot"). Kodi otherwise scanned their contents, and treats
  .ts code files as video.
- Fixed the first sync failing with "Invalid field selection sharedWithMe".
- A sign-in in progress now survives a Kodi restart.
- The setup guide now includes adding yourself as a test user, and makes publishing the
  app an optional last step.
- Status is shared through a file instead of a Kodi window property, and the WebDAV
  server never calls into Kodi while answering a request.
- The icon is now a full square, so it fits Kodi's frames without dark corners.
- Kodi shows a notification when Google stops accepting the sign-in (every 7 days while
  the Google app is in Testing), so Drive doesn't just go quiet.
- Sign-ins made with a browser on the Kodi device itself finish automatically (Google
  returns to http://127.0.0.1:<WebDAV port>/callback). Google blocks WebView-based TV
  browsers, so this needs a full browser such as Firefox.
- Adds a stall recorder (addon_data/.../stall.log) for diagnosing hangs.
